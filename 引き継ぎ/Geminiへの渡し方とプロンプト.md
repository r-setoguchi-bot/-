# Gemini に、このシステムを理解させる方法とプロンプト

## おすすめの方法（Gem を作る）

Gemini の「Gem（カスタムGem）」は、指示（プロンプト）と、資料のファイルを、あらかじめ登録しておけます。登録した資料を、いつでも読んで答えてくれるので、毎回、資料を貼り直す必要がありません。引き継ぐ人が、「このGemに聞けば、このシステムのことが分かる」状態にできます。

### 登録する資料（3つ）
1. `システム説明書.md`（全体の説明。「Googleドキュメント」に貼り付けて保存したものを登録すると、確実に読めます）
2. `ソースコード一式.txt`（6つのコードを、1つのテキストにまとめたもの）
3. 必要なら、スプレッドシートの「リスト」の**見出し行だけ**（個人情報は入れない）

> 注意: お客様のメールアドレス、店舗名の一覧、APIトークンは、**登録しない・貼らない**。説明書とコードには、含まれていません。

### Gem の作り方（画面の操作）
1. Gemini（gemini.google.com）を開く。
2. 左のメニューの「Gem マネージャー」→「新しい Gem」を押す。
3. 名前: `年末年始アンケート 引き継ぎアシスタント`
4. 「指示」の欄に、下の「Gemにそのまま貼る指示」を貼る。
5. 「知識」の欄で、上の資料（1と2）を追加する。
6. 保存する。共有したい人（引き継ぐ人）に、共有する（Gem の共有機能）。

（Gem が使えない契約の場合は、下の「Gem が使えない場合」を見てください。）

## Gem にそのまま貼る指示

```
あなたは、「年末年始アンケート自動化システム」の引き継ぎアシスタントです。
このシステムは、株式会社クリメンが、約1,240契約のお客様に、年末年始の特別回収の希望をGoogleフォームで集めるために、Google Apps Script で作ったものです。
知識として登録された「システム説明書」と「ソースコード一式」だけを根拠に、日本語で答えてください。

【答え方のルール】
1. 登録された資料に書いていないことは、推測で断定せず、「資料には書いていません」と言ってから、考えられる可能性を、そう分かるように書く。
2. 操作の説明は、「どの画面の、どこを押すか」「どの関数を実行するか」が、そのまま真似できる、具体的な手順にする。専門用語は、できるだけ使わず、使うときは、1行で説明する。
3. コードを直す提案をするときは、(a) どのファイルの、どの関数か、(b) 直す前と後のコード、(c) 同時に直さないといけない、ほかのファイルの場所（説明書の「修正するときの注意」を参照）、(d) 直したあとの確認方法、を必ず書く。
4. お客様にメールが届く操作（案内メールの本番送信、控えメールの本番モード）、フォームの作り直し、シートの内容を消す操作は、操作の前に、必ず、影響と、確認する点を伝える。`INVITE_MODE` と `RESP_MAIL_MODE` の扱いは、特に慎重に説明する。
5. APIトークンなどの秘密の値、お客様のメールアドレスや個人情報は、聞かない・出力しない。ユーザーが貼ろうとしたら、止めて、伏せる方法を伝える。
6. 質問があいまいなときは、1〜2個だけ、確認の質問をしてから答える。
7. 答えの最後に、「次にやること」を、1〜3個、書く。

【システムの要点（資料の要約。詳細は、資料を見ること）】
- kintone契約管理(契約中のみ) → buildListFromKintone → リスト → startFormCreation(フォームを約900件作成) → startInvitations(案内メール) → 回答集計(2時間ごと)・控えメール → 業者依頼済に○でフォームを閉じる → 11/30 23:59に全フォームを自動で閉じる。
- フォームは「メールアドレス × 契約者」ごと。複数店舗は、1店舗1ページ。各店舗のページに住所を出す。
- 安全装置: INVITE_MODE=on かつ 2026/10/15 09:00以降でないと、案内メールは本番送信されない。RESP_MAIL_MODE=on でないと、控えメールはお客様に送られない。
```

## 最初に、Gemini に、全体を理解させるためのプロンプト（Gem を作らない場合）

ChatGPT・Gemini などのチャットに、`システム説明書.md` と `ソースコード一式.txt` を添付して、次を送ります。

```
添付した2つの資料は、「年末年始アンケート自動化システム」（Google Apps Script）の説明書と、ソースコードです。
私は、このシステムを、他の人から引き継ぐ担当者です。プログラミングは、あまり詳しくありません。
次の順番で、日本語で、答えてください。

1. このシステムが、何を自動化しているか、3〜5行で説明してください。
2. 全体の流れを、「いつ、誰が、何をするか」の表にしてください（準備、10/15、10/15〜11/30、11/30以降）。
3. ファイル（6つ）と、その役割を、表にしてください。
4. 「やってはいけない操作」「お客様に、メールが届いてしまう操作」を、リストにしてください。
5. 私が、最初に、理解しておくべきことを、重要な順に、5つ挙げてください。
6. 説明書とコードを比べて、食い違いや、説明が足りない所があれば、教えてください。
```

## よく使う質問のテンプレート

### A. 状況を診断してほしい
```
次の状況になっています。原因として考えられるものを、可能性が高い順に、確認方法つきで教えてください。
状況: （例: 「フォーム作成が、200件で止まって、進まない」）
実行ログ: （ログを貼る。ただし、メールアドレスやトークンは伏せる）
```

### B. 仕様を変えたい
```
次のように変えたいです。
変更内容: （例: 「案内メールに、問い合わせ先の電話番号を入れたい」）
どのファイルの、どこを直せばよいか、直す前と後のコード、ほかに直す場所、直したあとの確認方法を、教えてください。
```

### C. 操作の手順を知りたい
```
次の作業をしたいです。画面のどこを押すかまで、具体的な手順で教えてください。
作業: （例: 「要確認の店舗に、アドレスを追加して、フォームを追加で作りたい」）
```

### D. コードの意味を知りたい
```
`回答集計` の `respApplyRequestedStatus` が、何をしているか、プログラミングが分からない人にも分かるように、説明してください。
```

### E. 来年度に使い回したい
```
来年の年末年始（期間: ○年○月○日〜○年○月○日）に使い回します。
直す場所を、全ファイルから、洗い出して、チェックリストにしてください。
```

## Gem が使えない場合・ほかの方法

1. **NotebookLM**（Google）: 「ソース」に、説明書とソースコードを登録すると、その資料だけを根拠に、答えてくれます。どの資料のどこに書いてあるか、引用も出ます。「資料に基づいた答え」を、確実に欲しいときに、向いています。
2. **Google Drive に置いて、Gemini から参照する**: 資料を、Googleドキュメントにして、共有フォルダに置き、Gemini の画面で、`@` でそのドキュメントを指定して質問する。
3. **Apps Script の画面で、Gemini に聞く**: コードを、1ファイルずつ、貼って質問する（コードの意味や、小さな修正に向いています。全体の流れは、説明書のほうを渡してください）。

## 資料の更新
システムを変えたら、`システム説明書.md` と `ソースコード一式.txt` も、更新してください（Claude に「説明書とソースコード一式を、最新にして」と頼めます）。Gem の「知識」にも、更新後のファイルを、入れ直してください。
