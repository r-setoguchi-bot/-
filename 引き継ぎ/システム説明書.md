# 年末年始アンケート自動化システム 説明書（引き継ぎ用）

この文書は、「年末年始アンケート自動化」を引き継ぐ人（と、その人が使うAI）が、全体を理解して、運用・修正できるようにするための説明書です。
作成時点: 2026年10月13日（最終更新）。対象: 2026年12月30日〜2027年1月3日の年末年始特別回収。

> 注意
> - この文書には、APIトークンなどの秘密の値、お客様の個人情報（アドレスなど）は含めていません。AIに質問するときも、これらを貼らないでください。
> - 本番のメール送信は、お客様に届きます。「安全のしくみ」（第7章）を必ず読んでから操作してください。

---

## 1. 何のシステムか

株式会社クリメンの契約管理（kintone）にある、契約中の約1,240契約について、年末年始の特別回収の希望を、Googleフォームで集めるシステムです。人の手でやると何日もかかる、次の作業を自動化しています。

1. kintone から、契約中のお客様のリストを作る（メールアドレス・回収曜日・住所つき）
2. お客様ごとに、Googleフォームを自動で作る（約900件）
3. お客様に、案内メールを自動で送る（会社のアドレスから、1通ずつ）
4. 回答を、1つのシートに集める。再回答を検出する
5. 回答した人に、回答内容の控えメールを送る
6. 業者へ依頼した店舗のフォームを閉じる。締切の日時に、全フォームを閉じる
7. 上記を、別の処理で二重に検証する

実行環境は Google Apps Script（Googleスプレッドシートに紐づいたスクリプト）です。サーバーは不要です。

## 2. 全体の流れ（時系列）

| 10/15 09:00以降 | 案内メールを送る | `INVITE_MODE` = `on` にして `startInvitations` |
| 10/15〜11/15 | お客様が回答。2時間ごとに自動で集計。回答のたびに控えメール | （自動） |

## 3. 構成（ファイルと役割）

Apps Script のプロジェクト名は「年末年始アンケート自動化」です。1つのスプレッドシートに紐づいています（コンテナバインド）。ファイルは次の6つです（Apps Script 上の名前は拡張子 `.gs`、リポジトリ上は `.js`）。

| ファイル | 役割 | 主な関数 |
|---|---|---|
| リスト作成 (`kintoneリスト作成.js`) | kintoneから契約中を取得し、フォーム作成用のリスト・要確認・契約状況一覧のシートを作る | `buildListFromKintone` `updateContractStatusList` `dumpKeiyakuFields` |
| フォーム作成 | リストの店舗を、「メールアドレス × 契約者」ごとにまとめて、Googleフォームを自動作成する。6分制限は、時間主導トリガーで自動継続して避ける | `startFormCreation` `stopFormCreation` |
| 案内メール送信 | 作成済みフォームごとに、案内メールを1通ずつ送る。送信記録を残して二重送信を防ぐ | `sendTestInvitations` `startInvitations` `stopInvitations` |
| 回答集計 | 全フォームの回答を1シートに集める。再回答・業者依頼・締切の処理。控えメール送信 | `startResponseCollection` `setupResponseCollectionTrigger` `closeRequestedForms` `closeAllFormsAtCutoff` `sendSampleReceiptMail` |
| 検証 | 上の処理とは別に、kintoneを読み直して、リスト・フォームを二重に検証する（何も書き換えない） | `verifyKintoneListData` `verifyListData` `verifyCreatedForms` `startFullFormVerification` |
| 設定確認 | スクリプトプロパティと接続の確認。確認が済んだら削除してよい | `checkSettings` `findEmailFields` `findAddressFields` |

（別に、`コード.js` という、LINE WORKSのチャットボットのコードが、同じリポジトリにある。このシステムとは無関係なので、触らない。）

各ファイルは、先頭のコメントに、使い方を書いてあります。ファイル同士は、できるだけ独立していて、共通の定数（質問の文言、期限の文言、列の位置）は、同じ値をそれぞれのファイルに書いてあります。**値を変えるときは、全ファイルをそろえること**（第10章）。

## 4. データの流れとシート

```
kintone「契約管理」アプリ（契約種別=契約中のみ）
   │  buildListFromKintone
   ▼
[リスト_kintone] [要確認] [契約状況一覧]   ← 内容を確認し、検証して、
   │                                         「リスト_kintone」を「リスト」に名前変更して採用
   ▼
[リスト]  ── startFormCreation ──▶ Googleフォーム（約900件）＋ [メール送信用]
   │
   ├─ startInvitations ──▶ 案内メール ＋ [案内メール送信記録]
   └─ startResponseCollection ──▶ [回答集計] ＋ 控えメール
                                    │ 「業者依頼済」に ○ → フォームを閉じる
```

### 「リスト」シートの列（フォーム作成・案内・集計・検証は、この列の位置に依存する）

| 列 | 内容 |
|---|---|
| A | 店舗名（契約店舗名称） |
| B | メールアドレス（送信先） |
| C | 業者名（収集業者：名称。料金の判定に使う） |
| D〜H | 12/30、12/31、1/1、1/2、1/3 の各日。回収できる日に `○`（1/1は回収不可で、空） |
| I | フォームURL |
| J | フォームID |
| K | フォーム作成状況（`送信済` / `エラー` / 空） |
| L〜P | 5つのアドレス項目の元の内容（優先順位順） |
| Q | 契約者（顧客名称） |
| R | 店舗住所（〒郵便番号 住所）。フォームの店舗ページと控えメールに載せる |

### その他のシート

- 要確認: フォームを作れない契約と、その理由（アドレスなし／ダミーのみ／形式が正しくない／可燃の回収曜日なし／期間中に回収できる日なし）
- 契約状況一覧: 契約中の全件について、状況（フォーム作成済／未作成／エラー／要確認）と、回答状況の管理用一覧
- メール送信用: 作成したフォームごと、店舗ごとの、アドレスとURLの一覧（確認用）
- 案内メール送信記録: 案内メールの送信結果（フォームID・送信先・結果・日時）。**同じフォームに二重に送らないための記録なので、消さない**
- 回答集計: 店舗ごとに1行。回答日時、特別回収、各日の○×、担当者名・電話、回答回数、再回答、依頼後の回答、業者依頼済（手入力）、依頼確認日時、フォーム受付、控えメール
- 検証結果_○○: 検証の結果（対象ごとに別のタブ）

## 5. 重要な仕様（決めたこと）

### アドレスの選び方
kintoneの5つの項目を、次の優先順位で見て、**最初に見つかった正しいアドレス**を送信先にします。
1. 年末年始　回答アドレス①
2. 年末年始　回答アドレス②
3. 案内等送付先メールアドレス:(to)
4. 送付先別：e-mail（項目名に注意書きが付いているので、フィールドコード `送付先別mail1` で指定）
5. 契約時の顧客担当：メールアドレス

- 1つの項目に複数のアドレスが入っていても、`,` `;` `、` 空白・改行で分けて取り出す。`mailto:` は外す。
- `dummy` で始まるアドレスは、ダミーなので使わない（`dummy@clean.maintenance.co.jp` が多くの契約者に入っていて、他社の店舗名が見えるおそれがあるため）。
- 使えるアドレスが1つもない契約は、「要確認」に入れる。

### フォームは「メールアドレス × 契約者」ごと
- 同じ契約者（会社）の、同じアドレスの店舗は、1つのフォームにまとめる（複数店舗のフォーム）。
- **同じアドレスでも、契約者が違えば、別のフォーム、別の案内メール**にする（経理代行などで、1つのアドレスに複数の会社がある）。
- 案内メール・フォームには、`【ご契約者】` に会社名を出す。

### フォームの構成
- 1ページ目: 担当者名、電話番号、ご不明点・ご要望（任意）
- 2ページ目以降: **1店舗につき1ページ**。「希望日の選択（1/3店舗目）」のような見出し。店舗名、**ご住所**、特別回収料金、各日の「希望する／希望しない」（必須）
- 「すべて希望しない」という選択肢は、**ない**。希望しない場合も、各日で「希望しない」を選んでもらう（「希望すると答えたのに、全日×」という矛盾を避けるため）。
- 料金: 標準は 7,000円/1日。業者別: 有限会社長澤商事 10,000円、株式会社光栄和 20,000円、鍵本産業株式会社 10,000円（`フォーム作成` の `FORM_VENDOR_FEES`）
- 店名が変わっていたり、同じ屋号の店舗があっても、お客様が店舗を特定できるように、各店舗のページに住所を出す。

### 回答の扱い
- 同じフォームに複数回答があれば、**最新の回答が有効**。「再回答」の列に「あり（内容は同じ／内容が変わった）」と出て、変わった行は黄色。
- 控えメール: 回答のたびに、フォームのURLを送ったアドレスへ送る。店舗ごとの表（日付を横に並べ、○＝希望する、×＝希望しない）、住所、変更方法、「業者の都合などで回収日や料金を変更する場合は、改めて連絡する」旨を書く。再回答なら、件名が「（再回答）」になる。
- 控えメールの遅れ: 回答の集計が2時間ごとなので、控えメールは、最大2時間遅れる。

### 業者依頼済と、フォームを閉じる
- 「回答集計」の「業者依頼済」に `○`（何か入力すれば有効）を入れる → 1時間ごとの確認で、フォームの受付が自動で止まる。
- **同じフォームの全店舗に印があるときだけ**止まる（1店舗だけでは止まらない）。印を消すと、再開する。
- 依頼後に回答があった行は、赤色で「依頼後の回答：あり」と出る。

### 期限
- お客様に案内する回答・変更の期限: **2026年11月15日(日)**（文面に書くだけ。フォームは閉じない）
- 実際にフォームを自動で閉じる日時: **2026/11/30 23:59**（`RESP_CUTOFF_AT`）。閉じたフォームには、「回答受付は終了しました。変更は株式会社クリメンまで連絡」と出る。

## 7. 安全のしくみ（お客様に誤ってメールが届かないように）

1. 案内メールは、`INVITE_MODE=on` **かつ** 2026/10/15 09:00 以降でないと、本番送信しない（コードの `INV_NOT_BEFORE`）。
2. 控えメールは、`RESP_MAIL_MODE=on` でないと、お客様に送らない。`test` のときは、`RESP_MAIL_TEST_TO` だけに送る。
3. テスト送信（`sendTestInvitations`、`sendSampleReceiptMail`）は、テスト用アドレスだけに送る。記録にも残さない。
4. 案内メールは、1通ごとに「案内メール送信記録」に記録し、同じフォームには二重に送らない。
5. 送信元アドレスが使えないときは、送る前にエラーで止まる。
6. 実行は、ロックで排他制御（二重起動しない）。
7. メールの1日の上限（Workspace で、約1,500通）に達したら、続きを数時間後に自動で再開する。案内メール900通と、控えメールの合計に注意。

### 自動で続ける処理の仕組み（6分制限と、一時エラー対策）
フォーム作成・案内メール送信・回答集計・全件検証は、1回の実行が約4.5分で区切り、時間主導トリガー（1分後）で、続きを自動で実行します。
- **保険の予約:** 開始時に、7分後に再開する「保険のトリガー」を作る。強制終了しても、7分後に再開する。
- **続きの予約のやり直し:** Googleの一時的なサーバーエラーで、トリガーを作れないことがある。2・4・8・16・32秒待って、5回まで、やり直す。先に続きの予約を作ってから、保険の予約を消す（予約がすべて失敗しても、保険が残る）。
- **フォーム作成のやり直し:** 1件のフォーム作成が、Googleの一時的なエラー（`Failed to retrieve form data` など）で失敗したら、3回までやり直す。それでも失敗した行は、K列が「エラー」になり、自動では再挑戦されない（同じ行で止まり続けないため）。
- 2026/10/12 の本番のフォーム作成では、続きの予約が失敗して、処理が途切れる事故があった（上の対策は、そのあとに入れた）。作成の途中で止まったら、`startFormCreation` をもう一度実行すれば、続きから再開する。

## 8. 運用手順（Runbook）

### 8-1. 全件のフォーム作成（準備）
1. 前提: `FORM_TEST_LIMIT` `FORM_TEST_MULTI` が**ない**こと。`INVITE_MODE` が**ない**こと。`RESP_MAIL_MODE` が `test` か未設定。
2. 「リスト」のI〜K列が空であること（残っていると、そのフォームが作成済みとして扱われる）。
3. `buildListFromKintone` → ログの「うち作成済みを引き継ぎ 0 件」を確認 → `verifyKintoneListData`（エラー0件）→ 「リスト_kintone」を「リスト」に名前変更（古い「リスト」は削除）。
4. `startFormCreation` を1回実行。約4時間（約900件、1件あたり約14秒）、自動で続く（1回4.5分で区切り、1分後に続きを実行する。1回に約20件。強制終了に備えて、7分後の保険トリガーもある。Google Workspace のトリガーの1日の実行時間の上限は6時間なので、収まる）。
5. K列が「エラー」の行があれば、その行のK列を消して、`startFormCreation` をもう一度実行する（その店舗だけ作り直す）。
6. 全部「送信済」になったら、`startFullFormVerification`（全件検証。約45〜60分、自動で続く。エラー0件を確認）、Driveのフォルダのフォーム数、数件を目視。
7. `setupResponseCollectionTrigger` を1回実行（2時間ごとの集計、1時間ごとの業者依頼の確認と、締切の確認を登録）。

### 8-2. 案内メールの送信（10/15）
1. 案内メールの文面を最終確認（`案内メール送信` の `invBuildMail`、件名 `INV_SUBJECT`）。文面を変えたら、`sendTestInvitations` で、自分に送って確認。
2. `RESP_MAIL_MODE` を `on` にする（お客様が回答したら、すぐ控えメールが届くように）。
3. `INVITE_MODE` を `on` にして、`startInvitations` を実行（10/15 09:00以降）。900通。1日の上限に達しても、自動で続く。
4. 「案内メール送信記録」で、結果を確認。「失敗」の行は、その行を消して、もう一度 `startInvitations` を実行すると、送り直す。

### 8-3. 回答の集計と、業者への依頼
- 自動で2時間ごとに集計される。すぐ見たいときは `startResponseCollection`。
- 業者に依頼した店舗は、「回答集計」の「業者依頼済」に `○`。すぐフォームを閉じたいときは `closeRequestedForms`。
- 11/30 23:59に、全フォームが自動で閉じる。

### 8-4. リストの更新（途中で、契約や住所が変わったとき）
1. kintoneを直す。
2. `buildListFromKintone` を実行 → 「リスト_kintone」ができる（作成済みのフォームのURL・ID・状況は、店舗名で引き継がれる）。
3. 検証して、問題なければ、「リスト」と差し替える。
4. `startFormCreation` で、足りない分だけ、フォームを追加で作る。
- **注意:** 作成済みのフォームは、内容を書き換えない。内容を変える場合は、そのフォームをゴミ箱へ移し、「リスト」のI〜K列（その店舗の行）を消してから、作り直す。
- 要確認（アドレスがない店舗など）は、kintoneにアドレスを追加して、上の手順で、追加で作れる。

### 8-5. 途中で止めたい
- フォーム作成: `stopFormCreation`
- 案内メール: `stopInvitations`
- 回答集計の自動実行: `removeResponseCollectionTrigger`

## 9. 検証（二重チェック）

`検証` は、リスト作成とは**別の実装**で、kintoneを読み直して照合します。何も書き換えません。結果は、「検証結果_○○」シートの「重大度」で見ます。エラー＝直してから進める、警告＝内容を見て判断、情報＝参考。

- `verifyKintoneListData`: 「リスト_kintone」を検証（差し替える前）
- `verifyListData`: 「リスト」を検証
- `verifyCreatedForms`: 作成済みフォームを、20件抜き取りで検査（店舗見出し、住所、日付の質問の数）。Driveのフォルダとも照合
- `startFullFormVerification`: **全フォームを1件ずつ開いて**、あるべき形（題名、説明文、項目の並びと数、必須、店舗ごとのページ・住所・料金、各日の質問と選択肢）と照合する。約900件で数十分。自動で続く。結果は「検証結果_フォーム全件」シート。途中で止めるときは `stopFullFormVerification`
- 照合する内容: 店舗名の重複、`【` `】` を含む店舗名（集計できなくなる）、送信先アドレス、回収曜日（○の位置）、契約者、住所、業者名、要確認との突き合わせ、アドレスの入力ミス（`gmial.com` など）、同じアドレスの複数契約者（情報）
- 現状（2026/10/12）: エラー0件、警告0件、情報201件（ダミーアドレス、電話番号が入っているアドレス欄、1つのアドレスに複数の契約者）。

## 10. 修正するときの注意（値をそろえる場所）

| 変更するもの | 変更する場所 |
|---|---|
| 質問の文言（担当者名・電話・コメント） | `フォーム作成` の `FORM_Q_*` と、`回答集計` の `RESP_Q_*`（回答の読み取りの目印なので、必ずそろえる） |
| 日付の質問の文言 `【店舗】12月30日(水)の収集を希望しますか？` | `フォーム作成` と、`回答集計` の `RESP_DATE_QUESTION_PATTERN`、`検証` |
| 回答期限・変更期限の表記 | `フォーム作成` の `FORM_DEADLINE_TEXT` `FORM_CHANGE_DEADLINE_TEXT`、`案内メール送信` の `INV_DEADLINE_TEXT`、`回答集計` の `RESP_CUSTOMER_DEADLINE_TEXT`、件名 `INV_SUBJECT` |
| 実際に閉じる日時 | `回答集計` の `RESP_CUTOFF_AT` |
| 特別回収の期間・日付 | `リスト作成` の `KLIST_DATES` `KLIST_NO_COLLECTION_DATES`、`検証` の `VER_DATES` `VER_NO_COLLECTION`、各ファイルの期間の表記（`FORM_PERIOD_TEXT` `INV_PERIOD_TEXT` `RESP_MAIL_PERIOD_TEXT`）。日付の列数（D〜H＝5列）を変えるときは、列の位置を使っている全ファイルを直す |
| 「リスト」の列の追加・並べ替え | 列の位置を使っている全ファイル（`フォーム作成`の`FORM_COL_*`、`案内メール送信`の`INV_COL_*`、`回答集計`の`RESP_COL_*`、`検証`の`VER_COL_*`、`リスト作成`の出力）。契約者はQ列、住所はR列 |
| ダミーアドレスの除外 | `リスト作成` の `KLIST_EXCLUDED_EMAIL_PATTERNS` と、`検証` の `VER_EXCLUDED_EMAIL_PATTERNS` |
| 住所に使うkintoneの項目 | `リスト作成` の `KLIST_ADDRESS_CODES` と、`検証` の `VER_ADDRESS_CODES` |
| 業者別の料金 | `フォーム作成` の `FORM_VENDOR_FEES` |

- 店舗名は、「回答集計」の識別キーです。**店舗名が重複すると、回答が混ざります**（検証でエラーになる）。店舗名に `【` `】` を含めない。
- kintoneの項目名は、**NFKC正規化（全角半角、空白の違いを無視）**で探している。見つからないときは、フィールドコードで指定する。
- 作成済みのフォームは、コードを直しても、**書き換わらない**。作り直しが必要。

## 11. 困ったとき（トラブルシューティング）

| 症状 | 原因と対応 |
|---|---|
| `リスト_kintone が見つかりません` | まだ `buildListFromKintone` を実行していない |
| 「項目のフィールドコードが分かりません」 | kintoneの項目名が違う。`dumpKeiyakuFields` で、項目名とコードを確認。`KLIST_FIELD_CODES` で指定 |
| `MAIL_FROM … 送信できるアドレスではありません` | Gmailの設定「アカウント」→「他のメールアドレスを追加」で、会社のアドレスを登録する（そのアドレスの受信箱で、確認コードを受け取る） |
| フォーム作成が2件で止まる | `FORM_TEST_LIMIT` が残っている。削除する |
| フォーム作成が途中で止まった | `startFormCreation` をもう一度実行。作成済みは、作り直されない |
| 「リスト」のK列が「エラー」の行 | そのフォームの作成に失敗。理由は実行ログ（`Failed to retrieve form data` などは、Googleの一時的なエラー）。その行のK列を消して、`startFormCreation` を再実行 |
| 続きの予約が切れて、処理が止まった（実行数に `server error` で失敗した実行がある） | 「実行数」の画面で最後の実行時刻を見る。止まっていたら、開始の関数（`startFormCreation` など）をもう一度実行する。作成済みの分は、作り直されない |
| 案内メールが送られない | `INVITE_MODE` が `on` か、10/15 09:00以降か、実行ログのメッセージを確認 |
| 案内メールの結果が「失敗」 | 宛先が正しくない、または送信エラー。記録シートのその行を消して、`startInvitations` を再実行 |
| 控えメールが届かない | `RESP_MAIL_MODE` を確認。控えメールは、最大2時間遅れる。「控えメール」の列の印（`テスト:` は、テスト送信済み。`失敗:` は、失敗。自動では再送しない） |
| 「回答集計」の見出しが違うという警告 | 見出しを変えた直後。前回までの集計は引き継がず、作り直される（「業者依頼済」の入力も消える。注意） |
| 実行が6分で強制終了する | 通常は、自動で続きを実行する。止まっていたら、開始の関数をもう一度実行 |
| トリガーが残って困る | Apps Script の「トリガー」の画面で確認・削除。`stop…` / `remove…` の関数でも止められる |
